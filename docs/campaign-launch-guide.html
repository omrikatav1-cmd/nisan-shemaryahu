2Supabase — על חשבון ניסן ניסן עומרי

הקוד כבר יודע לשמור לידים — חסר רק פרויקט אמיתי שניסן הבעלים שלו. הטבלה, ה-RLS וה-SQL כבר מוכנים בקובץ docs/supabase-setup.sql.

  1. ניסן נכנס ל-supabase.com ופותח חשבון (Sign up with Google — במייל של ניסן). זה לא על חשבון עומרי — החלטה מפורשת.
  2. New project → שם: nisan-leads, אזור: Frankfurt (eu-central-1) (הקרוב לישראל), סיסמת DB חזקה (לשמור).
  3. בפרויקט → SQL Editor → מדביקים את כל התוכן של docs/supabase-setup.sql → Run. זה יוצר את טבלת leads עם RLS ומדיניות "הוספה בלבד לאנונימי".
  4. Settings → API → מעתיקים 3 ערכים:
    • Project URL ו-anon public key — לא סודיים, אפשר לשלוח בצ'אט.
    • service_role key — סוד. מזינים אותו ישירות ב-Vercel Dashboard בלבד, לא שולחים בצ'אט ולא שמים ב-git.
  5. ב-Vercel → Project → Settings → Environment Variables מזינים (Production): 
    NEXT_PUBLIC_SUPABASE_URL      = https://xxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY = eyJhbGciOi...
SUPABASE_SERVICE_ROLE_KEY     = eyJhbGciOi...   (סוד)
    LEADS_DASHBOARD_PASSWORD כבר מוגדר.
  6. Redeploy ב-Vercel (משתני NEXT_PUBLIC_* נטמעים בזמן build — שינוי בלוח לא מספיק בלי דיפלוי מחדש).
  7. בדיקה: שולחים טופס דמה באתר → נכנסים ל-/leads (עם הסיסמה) → הליד מופיע. אם כן — מסלול המדידה חצי סגור.
מה כבר עובד אוטומטיתכל ליד נשמר עם service (מנעולן/אינסטלטור/הנדימן) ו-source_page (איזו עיר) — כך משווים בין 3 הקמפיינים ובין הערים לפי ליד אמיתי, בלי עבודת קוד נוספת.

3דומיין + וואטסאפ עסקי עומרי

דומיין

  1. קונים nisan-shemaryahu.co.il אצל רשם ישראלי (למשל domain the net / gandi) על שם ניסן.
  2. Vercel → Project → Settings → Domains → Add → מזינים את הדומיין → מגדירים את רשומות ה-DNS לפי ההוראות של Vercel אצל הרשם.

לא חוסם טכניתהקמפיין יכול לרוץ על nisan-shemaryahu.vercel.app, אבל דומיין אמיתי מעלה אמון ו-Quality Score. מומלץ לפני תנועה בתשלום.

וואטסאפ עסקי

האתר עדיין שולח למספר האישי של ניסן. פותחים WhatsApp Business (חינם) ואז מעדכנים בקוד 3 קבועים ב-lib/siteConfig.ts: OWNER_PHONE_INTL, OWNER_PHONE_DISPLAY, OWNER_PHONE_HREF → דיפלוי. לעשות זאת לפני שהקמפיין רץ, לא לפני שבונים אותו.

4GA4 + GTM + חשבון Google Ads ניסן אדיר

סדר נכון: GA4 → GTM → Google Ads. כולם חינם, כולם על מייל של ניסן.

  1. GA4: analytics.google.com → Admin → Create Property → שם Nisan Shemaryahu, אזור זמן ישראל, מטבע ILS → יוצרים Web data stream לכתובת האתר → מעתיקים את ה-Measurement ID (G-XXXXXXX).
  2. GTM: tagmanager.google.com → Create Container (Web) → מעתיקים את מזהה ה-container (GTM-XXXXXXX).
  3. מזינים ב-Vercel: NEXT_PUBLIC_GTM_ID = GTM-XXXXXXX → Redeploy. (הקוד מזריק את GTM אוטומטית ברגע שהמשתנה קיים — ר' שלב 5.)
  4. Google Ads: ads.google.com → פותחים חשבון על מייל ניסן → מדלגים על "Smart campaign" ועוברים ל-Expert Mode → מגדירים billing (כאן עומרי מזין את פרטי האשראי של ניסן, בהסכמתו) → אימות עסק.
  5. מקשרים: ב-Google Ads → Admin → Linked accounts → מקשרים את GA4 ואת Google Ads (וגם GA4 ↔ Google Ads דו-כיווני).
Local Services Ads — לא רלוונטי בישראלנכון ליולי 2026, LSA (המודעות עם "Google Guaranteed") לא זמינות בישראל. מתעלמים מכל הצעה של גוגל לפתוח LSA — עובדים עם Search קלאסי בלבד.

5חיבור המרות — הקוד כבר מוכן קוד מוכן אדיר

הארכיטקטורה: container אחד של GTM מנהל הכל (GA4 + המרות Ads + טריגרים על קליקים). זה אומר שאדיר יכול להוסיף/לשנות תגיות בלי שינוי קוד ובלי דיפלוי. מה שהקוד עושה כבר:

  • טוען את GTM ב-<head> ברגע ש-NEXT_PUBLIC_GTM_ID קיים (אחרת — כלום, אפס עומס).
  • שולח dataLayer event בשם lead_form_submit בכל שליחת טופס מוצלחת, עם lead_service ו-source_page.
  • כל כפתורי הטלפון הם <a href="tel:..."> וכל כפתורי הוואטסאפ הם <a href="https://wa.me/..."> — כך שטריגר קליק אחד ב-GTM תופס את כולם, בכל הקומפוננטות, בלי קוד נוסף.

מה אדיר מגדיר בתוך GTM (3 המרות)

המרהטריגר ב-GTMאיך
קליק טלפוןClick – Just Links, Click URL starts with tel:→ GA4 event call_click
קליק וואטסאפClick – Just Links, Click URL contains wa.me→ GA4 event whatsapp_click
שליחת טופסCustom Event = lead_form_submit (כבר נשלח מהקוד)→ GA4 event generate_lead
  1. ב-GTM מוסיפים תגית Google Tag (GA4 config) עם ה-G-XXXXXXX → Trigger: All Pages. (זה מפעיל GA4.)
  2. לכל אחת מ-3 ההמרות: יוצרים GA4 Event tag עם הטריגר המתאים מהטבלה. את הפרמטרים lead_service/source_page מושכים דרך Data Layer Variable ומצרפים ל-event הטופס.
  3. ב-GA4 → Admin → Events → מסמנים את שלושת ה-events כ-Key Event.
  4. ב-Google Ads → Goals → Conversions → New → Import → GA4 → Key Events → מייבאים את שלושתם כ-3 פעולות המרה נפרדות.
  5. מדליקים Enhanced Conversions for Leads ו-Consent Mode v2 (חובה ב-2026, ולפי ציות פרטיות — ר' widget הנגישות/פרטיות שכבר באתר).
  6. בודקים ב-GTM Preview + Google Tag Assistant: קליק טלפון, קליק וואטסאפ, שליחת טופס — כל אחד צריך להופיע. ב-Google Ads ההמרה מופיעה תוך ~3 שעות.
למה 3 המרות נפרדות ולא אחתכי כל קמפיין (מנעולן/אינסטלטור/הנדימן) צריך לדעת אם הליד שלו הגיע. עם lead_service + source_page שכבר נשלחים, אפשר לראות איזה קמפיין ואיזו עיר מביאים את הליד הזול ביותר — לא רק איזה קליק.

6מבנה הקמפיינים אדיר

מבנה מומלץ לתקציב קטן (מבוסס LocaliQ / WordStream / Optmyzr — ר' מקורות): קמפיין אחד לכל שירות, מפוצל שווה, רץ במקביל מהיום הראשון.

C · הנדימן/הנדימן~834 ₪/ח'הנדימן+עיר · תיקונים · החלפת ברז

הגדרות משותפות ל-3 הקמפיינים

  • סוג: Search בלבד. לכבות "Search partners" ו-"Display network" בהתחלה (בזבוז תקציב).
  • גיאו: רדיוס אור יהודה + הערים ברשימה (SERVICE_AREA_CITIES) — Presence (נמצאים באזור), לא Interest. לא תל אביב.
  • Match types: מתחילים ב-Phrase לגילוי + Exact על מילות הכוונה הגבוהה ("מנעולן אור יהודה", "נעלתי את עצמי בחוץ"). Broad רק אחרי שיש דאטה.
  • מילות שלילה (רשימה משותפת, 50+ מונחים): חינם, בעצמי, DIY, איך ל, מדריך, קורס, לימודי, שכר, דרושים, משכורת, + כל ערי תל אביב. לעדכן שבועית מדו"ח מונחי החיפוש.
  • Bidding: Manual CPC או Maximize Clicks בהתחלה (התקציב קטן מדי ל-Smart Bidding) → מעבר ל-Target CPA (60₪) רק אחרי 15+ המרות בכל קמפיין בנפרד.
  • Ad assets: Sitelinks (שירותים/אזור/צור קשר), Callouts (מחיר שקוף / מקומי / 24/6), Call asset (מספר העסק), Location.
  • תזמון: זמינות 24/6 — לכבות מודעות ביום המנוחה השבועי (לתאם עם ניסן).
מציאות התחרותעל מילות המפתח הגנריות מתחרים בעיקר אגרגטורים (pro.co.il, easy.co.il, midrag, b144) שקונים לידים — לא "ניסן אחר". לכן Quality Score והתאמת דף-הנחיתה הם מה שמכריע אם ניסן מרוויח או מפסיד את המכרז. 3 דפי הנחיתה כבר בנויים בדיוק לזה.

שבוע 1–2 (שלב הלמידה)

  • לא נוגעים כמעט. Smart Bidding/המערכת לומדת. שינויים מוקדמים מאפסים למידה.
  • כל 2–3 ימים: דו"ח מונחי חיפוש → מוסיפים שלילות (חוסמים בזבוז).
  • בודקים שהמרות באמת נרשמות (לא רק קליקים).

כלל ההכרעה

15 המרות לפני החלטהלא מכריזים "מנצח" בין וריאנטים/קמפיינים לפני 15+ המרות לכל אחד. בכנות: בתקציב הזה (~80 קליקים/חודש לקמפיין), מובהקות מלאה עשויה לקחת יותר מחודש. לתקצב לפי זה — לא לצפות תוצאה תוך שבוע. אחרי 15+ המרות בקמפיין: מעבר ל-Target CPA ותקצוב-מחדש לטובת מה שמביא לידים זולים.

10קווים אדומים — ציות

חובה לוודא בכל מודעה ובכל דף
  • אין הבטחת זמן הגעה ("עד שעתיים"/"תוך X דקות") — הוסר מכל האתר וכל הקופי. לא להחזיר עד שניסן נותן מספר מדיד שהוא באמת עומד בו.
  • אינסטלציה: אסור "מוסמך"/"רישיון"/"מורשה" — התעודה מגיעה בעוד ~חודשיים.
  • מנעולן: "מוסמך + אישור משטרה" — מאומת, מותר.
  • כל מחיר כולל מע"מ (חוק הגנת הצרכן תשמ"א-1981).
  • אין "אחריות בכתב", אין אזכור מילואים, אין ביקורות מומצאות בשום פורמט שנראה כמו ביקורת גוגל אמיתית.
  • כותרות עם [עיר]: תמיד לבדוק את אורך הכותרת אחרי החלפת [עיר] בשם העיר הארוך ביותר ברשימה — "ראשון לציון" (11 תווים) — לא רק עם ה-placeholder עצמו. כותרת שנראית תקינה עם [עיר] יכולה לחרוג מ-30 תווים ברגע שמציבים עיר ארוכה בפועל.
